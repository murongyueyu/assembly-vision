# 双目装配流程检查系统 — 视觉算法代码

树莓派 4B ＋ HBV-1714-2 S2.0 双目相机，检查黄铜舵轮摆件的装配流程。

**工件：4 类零件 —— 底座圆盘 / 立柱 / 轮盘组件 / 顶盖铭牌**，一料位一件；
料盘为**黑色 3D 打印件**（2×2 矩形槽），工作面铺**绿幕**当背景。
（早期方案文档里的「6 类零件 13 件、外圈与辐条分步安装」已作废，以 4 类为准。）

**当前状态：机械结构已搭好，相机已能出图。**
全套算法已在 PC 上离线跑通与回归测试；但真实画面的**背景是绿幕不是黑底**，
阈值与料盘标定必须现场重做 —— 见**第六节**。

## 一、最重要的设计原则：算法与硬件彻底解耦

```
   sources/  只管"图像从哪来"（真相机 / 视频 / 图片目录）
   core/     只管算法（只吃 numpy 数组与数据类，不碰相机、不碰界面）
   ui/       只管显示（只吃 UIState，不碰算法）
   pipeline  用线程把三者串起来
```

所以相机未到、支架未装时，`core/` 与 `tests/` 可以完全离线跑：

```bash
# 1) 生成合成测试图（用 STL 反解出的真实尺寸）+ 配套的合成标定
python tools/make_synthetic.py --out data/synthetic \
        --seq data/synthetic_seq \
        --calib config/calibration.synthetic.yaml

# 2) 不开界面跑一遍装配序列（含流程判断与终检）
python app.py --source images --path data/synthetic_seq \
        --calibration config/calibration.synthetic.yaml --no-ui --max-frames 400

# 3) 回归测试（4 个模块，不需要相机）
python tests/run_all.py
```

实测输出（离线，合成序列）：

```
[ok]   ✓ 步骤 1/4：放置底座圆盘 完成 | 步 1/4 | 辐条峰数 8/8
[ok]   ✓ 步骤 4/4：顶盖旋入拧紧 完成 | 步 4/4
[inspect] 齐套性: OK
```

## 三、算法速览

| 要求 | 做法 | 关键文件 |
|---|---|---|
| ② 实时识别零件与手 | 黄铜用 **饱和度 S + 色相上限** 分割（`s_max` 护栏挡绿幕，`V ≥ 80` 挡暗部色偏）；蓝手套用**色相 H + V 下限**分割（★ 绿幕工位必须抬高 `v_min`，见第六节） | `core/segment.py` |
| ① 零件合格性 | **单画面料盘逐位核验**：覆盖率判缺件（有件≈100%、无件≈0%）；旋转不变特征判完整 | `core/checks.py`、`core/features.py` |
| ③ 安装流程判断 | **装配状态谓词 ＋ 前置条件表**；取件事件 = 料位由有变无 且 手套压在该位 | `core/fsm.py`、`core/events.py` |
| ④ 组装齐全检查 | 轮盘高度判立柱 ＋ 极坐标数球头端凸起 ＋ 中心区判顶盖 | `core/checks.py`、`core/depth.py` |
| 位姿自检 | 料盘四角标记 → 每 0.5 s 重算单应；动了就自动补偿 ROI | `core/pose_check.py` |

### 四个必须记住的物理结论（都踩过坑）

1. **辐条计数要在料盘的轮盘槽里做，不要在装配体上做。**
   装配完成后，辐条臂之间的空隙里看到的是**下方的底座圆盘（也是黄铜）**，
   臂的位置没有对比度 → 在装配体上用"臂"的环带数，只会得到"整圈都是金属"。
   装配体上只能数**球头端伸出外圈的凸起**（`spoke_band_outer`）。

2. **立柱不能用"细长前景"判。**
   立柱是竖立的杆，俯视（含 20° 斜俯视）下它投影在底座圆盘内部
   （85 mm 长的杆在 20° 倾角下只投影约 29 mm，小于底座半径 29.65 mm），
   整根杆都被底座盖住。物理上它是旋进底座中心螺纹孔的，
   所以判据是 **「底座中心孔被堵住」**（`center_plug` 半径的小圆覆盖率）。

3. **蓝手套与笔记本键盘背光的色相完全重叠，色相分不开。**
   实测：手套 H∈[92,99]、S 中值 187、V≥91；笔记本蓝色键盘背光 H∈[91,104]、V≤146。
   两者 H 区间几乎重合，**只能靠「V 下限 + 面积闸门 + 形态」区分**
   （手套约 11 万像素；键盘背光最大连通域仅约 9 千像素）。
   所以演示工位有笔记本时 `glove.v_min` 必须从 40 提到 60~70。

4. **深度只保留一个用途：终检时判立柱。**
   B=120 mm 长基线，40–50 cm 处实测精度预期 1–2 mm。
   "顶盖是否拧紧"行程只有 1–2 mm，与噪声同量级 → **明确不做**。

## 五、踩过的坑（都已经修在代码里）

| 坑 | 现象 | 处理 |
|---|---|---|
| **OpenCV 不认中文路径** | `cv2.imwrite` 静默失败，文件根本没写出来 | 全项目统一用 `imgio.imread_safe / imwrite_safe`（`np.fromfile` + `cv2.imdecode`） |
| **离线播放太快** | 图片序列以几百帧/秒读完，12 Hz 的逻辑线程只看到随机帧，去抖与流程判断全失效 | `video.pace: true` 按 `video.fps` 实时播放 |
| **离线图被当成双目拼接** | 460 宽的图被切成 230 宽的半幅，ROI 全错 | `video.stereo: false`（默认不拆分） |
| **谓词判错了对象** | 写成"料盘槽里有没有"，而零件被拿走正是为了装上去 → 永远等不到下一步 | 谓词一律判**装配位**（`asm('base')` 等） |
| **抽检用了过期帧** | 合成序列循环后，全分辨率帧里装配位已经空了 | 帧新鲜度检查（差值 > 5 帧就重抓） |
| **`mm_per_px` 方向写反** | 返回"每毫米多少像素"(2.5) 而不是"每像素多少毫米"(0.4)，辐条环带被算到轮毂里 | 已修正并注释；所有调用方都是按 mm/px 用的 |
| **孔洞计数用了填充轮廓** | 画成 FILLED 就把孔填掉了，永远数出 0 | 只画轮廓线再洪泛填充；或直接传掩膜（`RETR_EXTERNAL` 的外轮廓本身不含内孔） |
| **自适应阈值双重缩放** | MAD≈0 时回退逻辑把阈值推到 3.0（>1），什么都数不出来 | 限额：阈值不超过"中值到 p95 距离"的 60% |
| **`minAreaRect` 角度是短轴** | `end_width_ratio` 稳定返回 1.00（看起来"很正常"，其实是退化了） | 主轴一律用 PCA 定 |
| **`straightness` 定义不对** | 直杆也返回 0.03（半宽/长度），像弯的 | 改成量**中心线**偏离直线的量 |
| **多半径投票被无效环带拖累** | 某个半径上没对比度 → 投 0 → 众数被拉低 | 0 峰的环带视为无效，不参与投票 |

## 六、真机现状与背景变更（★ 必读）

机械已就位、相机已能出图。实测两帧真实画面（料盘 + 4 类零件、戴蓝手套取件）得到：

### 6.1 背景：黑底 → 绿幕

| | 合成图（旧假设） | 真实画面（实测） |
|---|---|---|
| 背景 | 黑（V≈28） | **绿幕 H 中值 83，p2–p98 = [79, 95]，S 中值 255，V 中值 224~242** |
| 料盘 | 160×160 mm 四圆槽 | **黑色 3D 打印件，2×2 矩形槽，小于 160 mm** |
| 黄铜命中 | 有件≈100% | 前景占画面 7.5%，且**零件被拆成多个连通域** |

**绿幕为什么会误进黄铜掩膜**：绿幕 H≈84，而 `workpiece.yaml` 的黄铜上限是 `h_max: 45`，
安全余量 39 —— 单看色相是安全的。但绿幕**饱和度 S≈255 且亮度 V 很高**，
一旦现场光照变化让它向黄蓝方向漂移，就会从 `h_max` 一侧漏进来。
**保险做法：给黄铜加一条饱和度上限 `s_max`（实测黄铜 S 中值仅 87，绿幕 S≈255），
用一个 90 左右的 `s_max` 就能把绿幕彻底挡在门外 —— 这是比调 `h_max` 更稳的护栏。**

> ⚠️ **`s_max` 曾经是"配置里写了但不生效"**：`core/segment.py` 的 `_mask()` 原先只读
> `h_min / s_min / v_min` 作下限、`h_max` 作上限，**不读 `s_max`**。已修好（现在
> `h_max / s_max / v_max` 三个上限都支持，默认值 255/179 保证老配置行为不变）。
>
> **`s_max` 取值要小心**：实测四类零件自身的 S 分布是 **[52, 109]**（高光与氧化处会掉到 53），
> 所以取 90 或 110 都会**削掉零件自己的高光**。取 **180** —— 对绿幕（S≈255）仍有 75 的余量，
> 又完全不碰零件。

### 6.2 黄铜假阳性：光靠阈值切不干净，必须加全局 ROI

实测数据（这条推翻了"调阈值就能解决"的想法）：

| | S 分布 |
|---|---|
| 真实四类零件 | 中值 80~92，范围 **[52, 109]** |
| 原木桌面 / 手臂肤色（假黄铜） | 中值 **67~87**，p90 到 112 |

**两者在 S 上完全重叠**，所以再怎么调 `s_min/s_max` 都没法分开。实测图一里这类假块有
`17883 / 8443 / 7937 / 5740 px`——注意 `min_area_px` 提到 500 也挡不住它们（实测提到 3000 仍有
38013 px 的桌面块）。

**唯一可靠的解法是给黄铜检测加一个全局 ROI**（托盘 + 装配位的包围区域），
让黄铜只在工位范围内被检测。这与 **D2「位置即身份」** 完全一致，而且几乎零算力。
好消息是：**加了 `s_max=180` 之后，托盘内部的黄铜假阳性已经是 0.00%**，
所以只差把"桌面、笔记本、手臂"这些工位外区域排除掉。

### 6.3 蓝手套：V 下限的实测扫描

```
v_min=110 -> 真手套 83316 px  |  空场景最大蓝块  7882 px   ✗ 误报会过闸门(3000)
v_min=130 -> 真手套 79638 px  |  空场景最大蓝块  1230 px   ✓ 误报被面积闸门滤掉
v_min=150 -> 真手套 78725 px  |  空场景最大蓝块   774 px
v_min=190 -> 真手套 78022 px  |  空场景最大蓝块   368 px
```

已取 **130**：真手套只损失 4%，而笔记本屏幕/键盘背光产生的误报块掉到 `min_area_px=3000` 以下。
（`glove.v_min=40` 的旧值会让 47652 px 的笔记本屏幕被当成手，进而让 `frozen` 长期为真。）

### 6.4 深度：StereoBM 在本工位不可用，已改 SGBM

实测（判定闸门是 `depth.min_valid_ratio`）：

| 匹配器 | 整幅有效像素 | 料盘区有效 | 过闸门? | 料盘区视差散布 |
|---|---|---|---|---|
| StereoBM（原代码）nd=160 | **7.8%** | 9.3% | **✗** | **75 px（纯噪声）** |
| **SGBM** nd=256 bs=5 | **22.7%** | **45.8%** | ✓ | **6.6 px** |

根因是**料盘的纹理太弱**：料盘区 Laplacian 方差只有 **156**，是整幅（2490）的 6%，
局部块匹配器没有可比对的特征。SGBM 靠半全局平滑把有效像素提了 6 倍。

已改：`depth.matcher: sgbm`（可切回 `bm`）、`num_disparities: 256`、`block_size: 5`、
`min_valid_ratio: 0.12`。实测视差约 **221 px**（960 宽全分辨率），半分辨率约 110 px，
所以 256 档是合适的（SGBM 要求 16 的倍数）。

### 6.5 单眼分辨率与拼接方式（实测）

```
保存图 1920x720，接缝在第 959 列 → side_by_side，左右眼各 960x720
```

测试代码请求的是 `1280x480`，**相机没有接受**（DSHOW 下常见），实际输出 1920×720。
所以 `camera.yaml` 的 `capture.width/height` 必须写 **1920/720**——
`depth.py` 的 `stereoRectify(..., (W,H))` 和 `work_scale` 都依赖它。

### 6.6 现场标定必须按这个顺序重做

> 旧配置的病历（`glove.v_min=40` 时代）：实测在真实画面上命中 **18.2%**，
> 其中 y<210 的键盘区就占了 46123 px；最大误报连通域 47652 px，
> **面积、长宽比闸门全部放行**，会被 `pipeline` 当成 `glove_bbox`，
> 进而让 `frozen` 长期为真、界面一直显示「检测中…（手遮住了工件）」。

```bash
# 0) 先在 camera.yaml 里把白平衡与曝光锁死（否则一切阈值都会漂）
# 1) 重录素材：绿幕上依次摆 空料盘 / 单件 / 完整 / 缺件 / 戴手套取件 / 装配位
python tools/record.py --seconds 60 --out data/videos/real1.mp4
# 2) 料盘单应必须重做 —— 实物料盘尺寸与 160x160 不同，槽位坐标全部要重定
python calib/c3_tray_homography.py --manual
```
