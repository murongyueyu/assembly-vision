## c1 — 测 GSD 与真实焦距

### 要准备
- **一把钢尺**（或卷尺），能看清 mm 刻度
- 把钢尺**平放在料盘所在的同一个平面**上（★ 关键：不能拿在手里、不能比料盘高，
  否则测到的是另一个距离的尺度）
- 尺子尽量**水平**摆，与相机成像平面平行

### 运行
```powershell
& D:\miniconda\python.exe calib\c1_measure_fov.py --distance-mm 360
```

### 操作步骤
1. 弹出窗口，里面是相机画面
2. **在钢尺上点两个点**：鼠标左键点击。建议点相隔 **100 mm** 的两个刻度
   （比如 0 cm 和 10 cm 的位置），**点得越远越准**
3. 点错了按 **r** 重来；点完 2 个后按 **回车**（或空格）确认
4. 命令行会问「这两点的实际长度是多少 mm？」→ 输入 **100**
5. 会问工作距离 → 你已经用 `--distance-mm 360` 给了，不会再问

> 若窗口太大看不清，可以先按窗口的缩放。点击坐标是按原图算的，缩放不影响。

### 会输出
```
 两点像素距 = xxx.x px，实际 = 100.0 mm
 工作距离   = 360 mm
 >>> GSD           = 0.xxxx mm/px   （= 每像素 x.xxx mm）
 >>> 每毫米多少像素 = x.xxx px/mm
 >>> 反推焦距 f    = x.xxx mm   （厂家标称 3.0 mm / 80°；按像元 5.00 µm 反推）
     与标称偏差   = xx%   ...
 >>> 全画幅覆盖    = xxx.x x xxx.x mm  (1280x960)
```

### ★ 怎么判断这次标定可信
| 看什么 | 期望 | 不对说明什么 |
|---|---|---|
| **反推焦距 vs 3.0 mm** | 偏差 **< 15%** | 偏大 → 工作距离量得不对，或钢尺不在料盘平面 |
| **每毫米多少像素** | 约 **2.0~2.6 px/mm** | 差太远 → 上面两个输入有一个错了 |
| **全画幅覆盖宽度** | 约 **500~640 mm** | 若明显偏小 → 距离输小了 |

**把这三行原样发我。**

### 常见问题
- **点击没反应**：窗口没获得焦点，先点一下窗口标题栏
- **点完按回车没结束**：需要先点满 2 个点
- **画面全黑/全白**：光照问题。c1 不依赖分割，只要能看清刻度就行

## c2 — 双目标定，得到基线 B

### 要准备：棋盘格

用我生成的这张（工作区里）：

```
docs/chessboard_6x5_15mm_150dpi.png
```

**打印要求**：
- 打印时选 **「实际大小 / 100%」**，**不要选「适应页面」**（会缩放，尺寸就错了）
- 打印后**贴在硬纸板或亚克力板上**，让它平整、不翘、不弯（★ 翘曲是 RMS 变差的头号原因）
- 打印后可塑封或贴透明胶带，避免反光时也能用

**★ 打印完必须用钢尺量一下实际格边长**：
```
量 5 个格子的总宽 ÷ 5 = 实际格边长 mm
```
例如量到 5 格共 74 mm → 实际格边长 14.8 mm。**下一步要填这个数。**

> 为什么棋盘格做得这么小：单眼 640×720、像元 5 µm、焦距 3.0 mm，
> 在 36 cm 处水平视野只有约 **230 mm**。常见的 9×6 / 25 mm 棋盘内角点跨度就有 200 mm，
> 几乎占满画面，根本摆不出 20 组不同姿态。6×5 / 15 mm 的内角点跨度是 75×60 mm，留足余量。

### 运行
```powershell
& D:\miniconda\python.exe calib\c2_stereo.py --cols 6 --rows 5 --square 15.0
```
把 `--square` 换成你**实测**的格边长（上面量出来的数）。

### 操作步骤
1. 弹出窗口，左右两个画面并排（`pairs=0  L=True R=True`）
2. **举着棋盘格在相机前移动**，相机与棋盘格都尽量让棋盘格完整出现在**左右两眼**里
3. 屏幕左上角显示 `L=True R=True` 时，按 **空格** 抓一组
4. 抓错了按 **r** 撤销上一组

### ★ 抓组的诀窍（直接决定 RMS 好不好）
要抓 **20~30 组**，并且覆盖：

| 要覆盖 | 为什么 |
|---|---|
| **画面四个角 + 中心** | 标畸变必须有边缘数据 |
| **不同倾斜角**（前后左右各倾 15~30°） | 标旋转必须有姿态变化 |
| **不同距离**（把棋盘格前后移动 20~40 cm 范围） | 标焦距与基线需要深度变化 |
| **不同旋转**（棋盘格转 90°、45°） | 提高角点定位的约束 |

**不要**：只是平移、只在一个位置、只在一个平面内转。那样 RMS 一定很大。

> 距离范围注意：棋盘格**最近不要近于 10 cm**（会虚焦），
> 最远不要超过约 60 cm（角点太小定位不准）。工作距离 36 cm 附近最合适。

5. 抓够后按 **ESC** → 自动开始标定

### 会输出
```
 重投影 RMS = 0.xxxx px   合格 / 偏大，检查标定板
 >>> 基线 B = xx.xx mm
 fx=xxx fy=xxx cx=xx cy=xx
已写入: config/calibration.yaml
```
（可能还会打印一句「采用 8 参数有理畸变模型」，这是正常的，脚本会挑 RMS 更小的那个）

### ★ 怎么判断这次标定可信
| 看什么 | 期望 | 不对怎么办 |
|---|---|---|
| **重投影 RMS** | **< 0.5 px** | > 0.5：删掉明显偏的姿态重标；> 1.0：几乎肯定有姿态单一或棋盘格不平 |
| **基线 B** | 合理量级 **40~130 mm** | 若 3 mm 或 500 mm 这种离谱值 → `--square` 填错了 |
| **fx / fy** | 两者接近，约 **500~650** | 差很多 → 角点检测有问题 |

**把 `RMS` 和 `基线 B` 两行原样发我。**

### 常见问题
| 现象 | 原因 / 处理 |
|---|---|
| `L=False` 或 `R=False` 一直抓不了 | 棋盘格没完整进画面，或反光/虚焦。离远一点、正对镜头、避免顶光直射 |
| `有效组数 N 少于 12` | 抓太少，脚本拒绝标定。多抓几组 |
| RMS 一直降不下来 | 棋盘格没贴平（翘了）、姿态太单一、或打印尺寸被缩放导致角点间距与实际不符 |
| 按空格没反应 | 要先等 `L=True R=True` |
| 检测不到棋盘格 | 检查 `--cols/--rows` 是否与打印的一致（**内角点数**，不是方格数）：6×5 内角点 = 7×6 方格 |

## 标定产物

两个脚本都会写入 **`assembly_vision/config/calibration.yaml`**：

```yaml
fov:                              # ← c1 产出
  work_distance_mm: 360.0
  gsd_mm_per_px: 0.xxxx
  focal_mm_derived: x.xxx
  frame_width_mm: xxx.x
  frame_height_mm: xxx.x
stereo:                           # ← c2 产出
  baseline_mm: xx.xx
  K_left / D_left / K_right / D_right / R / T
  image_size: [640, 720]
  reprojection_rms_px: 0.xxxx
```
