# B 模块：D435 原生深度与高度验证

2026-10-18，rev.3s.2。本轮原生深度与人工定位测点的受控对照已完成；不声明全自动缺立柱识别或完整装配流程验收完成。

## 实现与边界

- 显式开启 depth.enabled=true、depth.backend=realsense 才开彩色和 Z16 双流；默认正式 camera.yaml 仍仅开彩色，A 模块来源 hash 不变。
- SDK 将深度对齐彩色，并按设备实际 depth_scale 换算毫米；同帧 SDK pointcloud 反投影为 XYZ 毫米，不使用旧 HBV 内参。0/空洞为 nan，right/right_full 始终为空。
- 显式裸桌面参考区拟合三维平面，测量目标到平面的法向距离。目标不参与拟合；不再从整幅图猜桌面。平面残差、内点比例、目标有效比例/点数/高度散布和跨帧散布均有门禁，参数在 config/depth_d435.yaml。
- 测量表面必须明确声明。wheel_patch测轮盘金属，cap_region测中央顶盖附近区域；两者不能混用。用户已确认当前测得为顶盖到底部，故本轮采用cap_region，表示相对绿垫的局部代表高度，不是整片轮盘的统一高度。当前为固定机位、固定测量区，不自动定位零件；移动相机、目标位置或改测量表面须重新选区及验证。
- 运行配置绑定设备序列号、对齐内参和 depth_scale，不符时拒绝高度。pipeline 不初始化旧双目匹配器，深度无效或超过2秒返回未知。
- 高度基线/容差只注入判据的内存配置副本。实际终检从 workpiece 的 assembly 字段取基线，仅写 calibration 字段不足以接通；此路径有回归覆盖。c5生成的候选默认baseline_accepted=false，原图表面核验及独立实测通过前不向终检提供基线，防止稳定的错选区读数生效。
- 立柱实时流程的高度辅助阈值 column_threshold_mm 暂不自动生成；需采底座与完整装配对照后决定。不修改工序或合格性算法；原主程序的旧几何与完整流程验收仍待对应模块处理。
- 当前B接口保留历史wheel_height_mm字段名，但cap_region数据表示顶盖测区相对绿垫的代表高度，不是轮盘顶面。受控实验只比较同一物理表面；缺顶盖、画面中没有对应表面、测点未定位时不能据此断言缺立柱。主程序尚无测区随零件自动关联/存在性门禁，因此baseline_accepted继续false，不将本次手动对照直接启用为无人值守终检。

SDK 机制依据：[RealSense 投影与单位说明](https://dev.realsenseai.com/docs/projection-in-realsense-sdk-2-0/)。SDK 点云保留实际反投影模型，不以理想针孔近似替代设备模型。

## 实验步骤

从仓库根目录 PowerShell 使用指定解释器。相机必须 USB3，开流和写盘需要普通桌面权限。以下输出目录必须是新的，工具拒绝覆盖。

```powershell
$py = 'D:\miniconda\envs\yolov11\python.exe'
& $py 'assembly_vision/tools/probe_native_depth.py' --out 'ai_测试工具/B模块深度/stream_next'
```

基线：先把四件组装成完整装配体，保留正常倾斜，放在料盘左侧绿垫上、完整入画，手退出。第一个窗口选平整空绿垫作为参考；第二个窗口按measurement-surface选同一块可见表面，当前cap_region选顶盖顶部小片，避开边缘和周围轮盘。每次鼠标拖矩形后按回车；C或ESC取消选区，此次不能形成有效基线，需用新目录重开。随后自动采30个有效样本。

```powershell
& $py 'assembly_vision/calib/c5_assembly_baseline.py' --native-depth calibrate --measurement-surface cap_region --frames 30 --out 'ai_测试工具/B模块深度/full_next'
```

成功才生成 camera.native-depth.json；过低高度、空洞或不稳定不会生成基线。report.json 含全部尝试与拒绝原因，首/末样本保存彩色PNG和深度/XYZ NPZ，可独立重算。只在退出后检查报告，关闭窗口或口头说完成不能代替结果。

独立正常检查：保留机位和目标位置，先不拆装，重新开流采样；随后另做重新摆放的重复性验证。无需再选区。

```powershell
& $py 'assembly_vision/calib/c5_assembly_baseline.py' --native-depth check --native-reference 'ai_测试工具/B模块深度/full_next/camera.native-depth.json' --native-label full --frames 30 --no-preview --out 'ai_测试工具/B模块深度/full_check_next'
```

缺立柱检查：先确认实物允许稳定地将轮盘和顶盖放在底座上，无需手扶；确认就绪后再开流。保留同一被测表面，native-label改missing-column、out换新目录。拆装后测点位置改变时追加--reselect-target，去掉--no-preview，只重选目标，不重选参考区、不改变原高度基线。报告target_selection会明确记为manual_reselection，这只验证人工定位后的深度高度差，不能宣称自动定位/自动识别缺立柱。先核对保存原图，不能拿绿垫或错误零件高度冒充缺立柱。缺少顶盖、手扶或场景无法稳定摆放时不作此对照；空洞为未知。

只有 B 高度数据和独立场景验证就绪、记录证据并将运行副本的baseline_accepted置true，才可通过 app.py --camera 指向该运行配置向终检提供原生基线。未接受的候选仍可用于独立check，但不能当已验收标定；这不代表旧料盘标定有效或已集成 A 模块 v5。

## 现场结构澄清与重开流复测（2026-10-18）

用户明确：正确装配后的轮盘本来就倾斜，类似日晷；尺量绿垫到轮盘中央、靠近顶盖的位置约67mm。此前要求轮盘水平不适用于实物，必须纠正；不能将空间高度散布全解释为坏深度或混入背景，倾斜表面本身也有高度梯度。已采选区66.31mm与约67mm仅为近似点位对照，不能据此声称亚毫米误差或整片轮盘统一高度。后续固定中心附近同一测量表面和倾斜姿态，不改成「最高点」或任意边缘。

沿用原选区重开流full_check_01，30帧高度中位0.6697mm、帧间P90-P10=1.7892mm；保存的原图显示装配体已移出画面，仅见绿垫、空盘及尺子。命令标签虽为full，不能作为正常装配或缺立柱样本。原报告标签/数值保留，experiment_status.json独立标注excluded_from_full_validation和实际空台场景，避免改统计掩盖实验前提不成立。已请用户将装配体放回、手和尺子退出，收到准备好后再重新选区与采集，不自动在摆放过程中开流验收。候选仍不接受，B现场验证未完成。

用户进一步澄清，量得应为顶盖到底部的高度，测量定义统一为绿垫到中央顶盖附近区域。收到「已放回，可以重新选区」后采full_baseline_03：参考[64,13,290,220]，目标[235,313,26,26]，30/30有效，高度68.0251mm、帧间P90-P10=0.6729mm。原图确认正常倾斜装配体和中央顶盖测点，运行配置补记measurement_surface=cap_region、用户近似尺量67mm；不混称轮盘顶面。

保持原位独立重开流full_check_02：30/30有效，高度67.7974mm、帧间P90-P10=0.9004mm，与_03差0.2278mm，height_matches_baseline=true；首帧原图确认装配体仍在相同位置。仅证明当前固定姿态/选区的短时重复性，粗略尺量不支持亚毫米绝对精度。缺立柱对照尚待用户确认安全稳定摆放；baseline_accepted仍false。
