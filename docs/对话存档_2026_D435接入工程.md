# 对话存档 2026 —— D435 接进工程（采集层）

> 本轮**只做一个模块**：**相机接入层**（与 `rev.3j` 同口径，属模块 G 的硬件接入范畴）。
> 只做「图从哪来」这一层：**没有动 `core/` 的阈值，也没有重跑标定**。
> 版本记录见 `docs/版本历史_详录.md 的 rev.3l；踩坑详录见 `docs/踩坑实录.md` **§2.38~§2.41**。

---

## 1. 起因：工程里根本没有能在 D435 上取图的路径

`rev.3j` 把 D435 "打通"到了「独立脚本能出图」，但 `assembly_vision/` 里：
`factory.py` 只认 `uvc | video | images`，而 `cv2.VideoCapture` **永远打不开 D435**。
于是 `app.py` / `tools/preview.py` / `calib/c3~c6` **一台真相机都打不开**。

★ 开工前先把**依赖顺序**理清了，这条比代码本身更重要：

```
P0-0 原文写的顺序：架相机 → 曝光 → 色域 → 木桌假阳性 → c3 → c4/c5/c6 → 【写源】
实际情况：          第 2~6 步全都要经 make_source(camera.yaml) 取图
                 ⇒「写源」不是收尾，而是它们的前置
                 （不然只能用 --source images 喂离线帧绕）
```
→ 所以本轮先做「写源」，这是**唯一能立刻推进、且不依赖把相机架到工位**的一步。

## 2. 交付物（全部在采集层）

| 文件 | 改了什么 |
|---|---|
| `assemvision/sources/d435.py` | ★ **新增** `RealSenseSource`：`open/read/close`、控件锁定（**先关自动曝光再给值**）、USB 3 自检、内参/GSD 查询、开流重试与**写清排查顺序**的报错 |
| `assemvision/sources/factory.py` | `d435 / realsense / rs` → `RealSenseSource`（**延迟导入**，没装 SDK 的机器不受影响） |
| `config/camera.yaml` | `source: d435` + 新 `realsense:` 段；HBV 段落**标注清楚但保留**（可一键回退）；`depth.enabled: false` |
| `tools/probe_d435.py` | ★ **新增**自检：设备信息 + 逐模式帧率/GSD/覆盖/过曝 + 存样张 + `--reset` |
| `tools/probe_camera.py` | 遇到 `source: d435` **拦下并指路**（那台不是 UVC 相机） |
| `tests/test_d435_source.py` | ★ **新增**：**假 SDK 的构造级契约测试**（19 组断言，不需要相机） |
| `tests/run_all.py` | 登记第 **12** 个模块；★ 顺带修掉 **GBK 控制台假崩** |

★ 设计取舍记一笔：
* `right=None`：D435 的深度是**固件算出来的深度图**，不是第二只眼睛的图像 ——
  塞进 `right` 会让 SGBM 拿深度图当右目匹配，出来全是噪声。接线属 **B 模块**。
* `depth.enabled: false`：否则 T5 会一直请求全分辨率帧却永远等不到右眼（白跑）。
* `left` 与 `left_full` 同源：只有一个彩色传感器，`want_full` 给不出更清楚的图
  （也不会更差）—— 想要更清楚只能整体换分辨率并重标。

## 3. 真机验收（三条都实跑过）

```powershell
# ① 接入层自检（设备/帧率/GSD/过曝/存样张）
& D:\miniconda\envs\yolov11\python.exe tools\probe_d435.py --modes 640x480,1280x720 --seconds 3

# ② 整条流水线（工程自己的源）
& D:\miniconda\envs\yolov11\python.exe app.py --no-ui --max-frames 90

# ③ 帧率（零件检测）
& D:\miniconda\envs\yolov11\python.exe tools\part_track_demo.py --bench --max-frames 150
```

| 检查 | 结果 |
|---|---|
| 设备 | RealSense D435 / SN 262322070302 / 固件 5.17.3.10 / **USB 3.2** |
| 640×480@30 | **30.0 fps**，fx=603.8、GSD@360mm **0.596**、覆盖 382×286mm、过曝 1.60% |
| 1280×720@30 | **30.0 fps**，fx=905.7、GSD@360mm 0.397、覆盖 509×286mm、过曝 1.20% |
| `app.py --no-ui` | 90 帧**退出码 0**，启动即认出 `RealSenseSource(...USB=3.2)` |
| `part_track_demo --bench` | 每帧均摊 **2.56ms**（分割 8.61ms 摊到 1/8），上限远高于相机 30fps |
| 离线回归 | **12/12 全绿**（含新增的 `test_d435_source`） |
| 端到端（合成序列） | 4 步全过、`齐套性: OK`、退出码 0 |

★ 没做：**`--windowed` 本轮没跑**（要显示器与相机同时在线）；标定链一步没重跑（那要相机架到工位）。

## 4. ★★ 三处「推算当实测」的纠错

| # | 原文档 | 实测 | 为什么错 |
|---|---|---|---|
| 1 | 640×480 → GSD **0.795** | **0.596** | 拿 720p 内参 fx=905.74 **等比外推**；而 D435 的 640×480 是**裁切模式**（FOV 55.9° vs 70.5°）—— 内参随模式变，不能换算（实录 **2.38**） |
| 2 | 640×480 覆盖 **509mm** | **382mm** 宽 | 同源错误。★ 连带影响**架设**：视野比 HBV 的 555mm 窄得多，工位要先量宽度 |
| 3 | 离线回归「**11/11 全绿**」 | 默认 GBK 控制台 **exit 1** | 输出里的 `✓`(U+2713)/`²`(U+00B2) GBK 打不出 → `UnicodeEncodeError` → 三个模块**假失败**（实录 **2.41**） |

## 5. ★ 两个环境坑（不是相机的问题，却伪装成"相机坏了"）

### 5.1 受限（Low 完整性）进程打不开 RealSense

同一台相机、同一份代码：用户终端里 `用户存档/predict.py` **正常**；
沙箱里 `query_devices()` 抛 `Mutex_TotalFailure`、`pipe.start()` 报 `No device connected`。

判据链（实录 **2.39**）：`pnputil /enum-devices /connected` 看到
`Intel(R) RealSense(TM) Depth Camera 435 ... Status: Started` ⇒ 设备/驱动都在
⇒ 再看"同一命令换个进程是否正常" ⇒ **是权限，不是相机**。

### 5.2 工作区子目录缺 Low 标签 → 受限进程写不进去

`assembly_vision\` 下**连新建空文件都被拒**，而工作区根目录能写；
DACL 里**明明有 Allow**（补 ACL 也无效）—— 是**强制完整性标签**（no-write-up）。
影响：`make_synthetic` / `c3~c6` / `probe_d435 --save` 这类要落盘的工具，
必须跑在**不受限**的进程里（实录 **2.40**）。
