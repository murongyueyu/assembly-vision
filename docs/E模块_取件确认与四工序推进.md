## 运行与语义

从assembly_vision目录执行：

```powershell
& 'D:\miniconda\envs\yolov11\python.exe' app.py --process-sequence config/process_sequence.yaml --windowed
```

E与独立C/D开关互斥；不传新开关保留旧行为。E复用D的冻结A v5与C观察器/双分割，同一原图、帧号、采集monotonic交D。不开B、旧装配ROI或终检；不改正式配置来适配现场。

D四槽正确稳定放行后自动锁存开工。操作名称、前置条件和效果读取workpiece，E配置仅绑定op1到slot_base、op2到slot_column、op3到slot_wheel、op4到slot_cap，启动验证四操作与四槽的一对一关系和前置可达性。取件确认只表示正确槽中零件取出，不能证明物理安装、紧固或高度正确。完成文案为「按取件顺序推定完成」。

确认器消费D逐槽状态：match确认正确在槽，missing表示C可靠空槽且无A当前冲突，unknown/wrong不作为取件。已确认match到连续稳定missing才产生pick；不要求手与空槽在同一时刻出现，手退出后的证据才有意义。初始E工程门槛为3个新帧且保持0.3秒；D自己的缺件稳定仍先执行，实际延迟并非0.3秒保证。所有槽当前证据均稳定后才推进；未知、遮挡、错件或待确认时暂停。只消费当前槽关联，不借盘外零件或历史轨迹顶替。

| 情况 | E行为 |
|---|---|
| 未通过D | 等待；确定D报警保留开工检查明细，不产生取件 |
| 当前应取件唯一稳定取出，其余未完成槽正确在槽 | 推进一个工序，记录带原始帧号的取件事件 |
| 越序或两个及以上未确认槽稳定空 | 红色报警、不推进；未确认件须放回正确槽后重试 |
| 已完成件稳定正确放回 | 回退到最早该步，撤销后续推定；后续件须放回重验 |
| 遮挡、未知、错件 | 不累计相应槽确认、不推进；保持已完成历史 |
| 重复帧 | 不增加计数、不重复事件 |
| 过期/方向拒识/来源失效、倒退或重复帧证据变化、长间隔 | 清未完成槽的连续在槽记忆，暂停；恢复后先重新见到match，不能把中断后的空槽补记成pick |
| 无进展超15秒 | 黄色等待下一步；不自动跳步或终结 |
| 窗口按R复位 | 清E历史/事件及D门禁，等待新的四槽放行；在途旧计算用代次隔离，不能复活复位前结果 |

E在锁内更新/展示原子快照，UI重复轮询不推进。开工后正常取件空槽由E解释，不再把D缺件红横幅作为工序失败；真实越序/多取/错件才显示红横幅。只读D动态allow_start可以因槽空变false，不能把它误当E已开工锁存被撤销。
