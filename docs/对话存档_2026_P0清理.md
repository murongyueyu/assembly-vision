## 二、四个真 bug（按发现顺序）

### 2.1 `hub_coverage` 恒为 `nan` —— 一行复制粘贴漏改

```python
covs.append(a.ring_coverage); rings.append(a.hub_coverage)   # ← rings 收了 hub 的值
```

`hubs` 永远是空列表 → 打印

```
外圈环带覆盖率 1.000   轮毂覆盖率 nan   顶盖覆盖率 1.000
```

**三个数全错位**（那个 `1.000` 其实是**轮毂**的值，`nan` 是空列表的均值）。

**★ 我在这一条上绕了很久。** 我一直认为 `_disc_coverage` 在某种输入下会返回 `nan`，
于是构造了 8 种异常输入去试：

```
center 含 nan / 含 inf / radius=nan / radius=inf / center 在画面外 /
radius 极大 / center 是 numpy nan ...
```

结果：**它任何情况下都不返回 nan（最差是 0.0）**。

> **教训（已写进 docs/现状与交接.md 的 P0-3）**：
> **看到 `nan` 先数一数"列表里到底有几个元素"，别先怀疑算法。**
> `nan` 最常见的来源不是数学，是**空集合求均值**。

### 2.2 装配位 `pose` 不一致 —— 同一个装配位，两处算出不同的圈

```
work_roi_mask()     装配位**跟着位姿修正**   ← 对
check_assembly()    用 self.tray.assembly_polygon_px()（标称坐标）  ← 错
assembly_flags()    同上                                        ← 错
```

实测：料盘挪 `tx=8.8mm` 时，两处差 **10.0px（8.7mm）**。
后果是「ROI 跟着料盘走了、**判定用的圈没走**」—— 圈住的和判的不是同一个地方。

**修法**：新增 `Qualifier.assembly_polygon_px(scale, pose=None)` 作**统一入口**，
`check_assembly` / `assembly_flags` 都加 `pose` 参数，`pipeline.py` 两处调用都传 `self._last_pose`。

> ★ 这一条**不是**为了"开放位置"才做的 —— 它本身就是 bug。
> 我一度把它归到 P1「开放位置」的实现要点里，**归错类了**：
> 「两处算法不一致」和「要不要开放位置」是两件独立的事。

### 2.3 `app.py --windowed` 一启动连崩两次 —— 测试盲区

```
(1) TypeError: OpenCVRenderer.__init__() got an unexpected keyword argument 'actions'
(2) AttributeError: 'OpenCVRenderer' object has no attribute 'frames_drawn'
```

两条都是「跨模块接口不一致」，而且**都只有 opencv 渲染器中招**：

- `QtRenderer` 有 `actions` 参数 → opencv 版没有
- `QtRenderer` 是 `QMainWindow` 子类、`__init__` 链路里自然调到了 `Renderer.__init__` → opencv 版没调

**而 `--windowed` 的默认渲染器就是 opencv** —— 所以**这条路径根本跑不通**。

**修法**：给 `OpenCVRenderer` 加 `actions` 并**真的接到按键上**
（`i` 手动抽检 / `r` 复位 / `q`·ESC 退出），补 `super().__init__()`。

**★ 根因不是这两个 typo，是测试盲区**：

```
--no-ui      一直有端到端测试覆盖
--windowed   一次都没跑过
```

> **教训（已写进 docs/现状与交接.md「另修 2」）**：
> **「只能手工跑」的那条路径最容易烂。**
> 凡是只能手工跑的路径，至少要有一个**构造级**的离线测试把它钉住 ——
> 于是新增 `tests/test_ui_renderer.py`：**逐字按 `app.py` 的真实参数**构造渲染器
> （只构造、不显示，不需要相机/显示器）。

### 2.4 「装好了却判缺辐条」—— 本轮最有价值的一个

**症状**（用户真机截图 + 40 多行日志）：
轮盘完整装好、8 根辐条清晰可见、界面显示"装配流程全部完成 4/4"、大对勾 ✅，
**但报「辐条峰数 0/8」「齐套性 NG, 缺失 辐条 5/8」，而且连续几十帧 `8/8` 一次都没出现过。**

**根因**：`count_spokes` 把半径带切成 `n_radii_bands=3` 个子带各自数峰，
再「取众数、**并列时取较小值**」。真机实测（30~35mm 切 3 带，每带仅 1.67mm ≈ **1.9px**）：

```
带(mm)        med    p95-med  阈值    峰数
30.0~31.7    0.000   1.000   0.600    8   ← ★ 球头只落在最内侧这个带
31.7~33.3    0.000   1.000   0.600    6
33.3~35.0    0.000   1.000   0.600    5
```

计数 `[8, 6, 5]` —— **三个全不同、没有众数** → 并列取较小值 → **5** → `5 < required(8)` → 假 NG。

**而同一帧整条 30~35mm 一次数（c5 的做法）是 8 峰、抖动 5.9°。**
→ **c5（标定）与 `check_assembly`（运行）在数同一批辐条，却用了两套算法。**

**物理原因**：球头只有 **Ø5mm**，在 0.8623mm/px 下**只有约 6px 宽** ——
落进哪个子带**是碰运气**。

**修法**：按**角度均匀度**挑最好的带（真辐条是均布的，"抖动最小"远比"票数最多"可靠）：

```
select=vote(旧)     -> count=5  抖动=inf   峰=[98, 135, 177, 262, 309]
select=uniform(新)  -> count=8  抖动=6.2°  峰=[6.2, 57.2, 99, 135, 177, 218, 262, 309]
```

6.2° 与 c5 当初**独立**扫出的基线（5.9°、峰
`[5.5, 57.5, 98.5, 134.8, 176.5, 219.5, 262, 310]`）**几乎逐度吻合 —— 互为独立验证。**

**★ 这个判据不是新发明**：c5 的 `sweep_band` 早就用它
（真辐条 5.9° vs 凑出来的 8 峰 33°）。这次只是把**同一条判据搬到运行路径上**。

**兜底**：所有候选带抖动都 > 15° 时**退回"峰最多"那个** →
让真缺陷被如实报出，而不是因为我们挑剔就报成 0（另一种假 NG）。

**验证**：

```
真机帧 asm_raw.png 跑完整 check_assembly:
   修复前  verdict=NG   missing=[辐条 5/8]
   修复后  verdict=OK   spoke=8/8  抖动=6.2°  missing=[]
合成图 少画 0/1/2/4 根 -> 仍准确数出 8/7/6/4   ← 真缺陷检出未变差
```

## 三、从这四个 bug 里提炼出的可复用判据

> 这一节比具体改动更值钱 —— 下次遇到同类症状直接照这个走。

| # | 判据 | 来自哪个 bug |
|---|---|---|
| 1 | **看到 `nan` 先数"列表里到底有几个元素"**，别先怀疑算法。`nan` 多半来自空集合求均值，不是数学 | `hub_coverage` |
| 2 | **同一个量在两个地方用了两套算法，迟早会打架。** 标定与运行必须共用同一条判据 | 辐条 8 vs 5 |
| 3 | **"并列时取较小值（宁少不多）"这类偏置要写清适用条件。** 在"没有真值可依"时是对的；一旦**有更强的几何信息**（辐条是均布的），"取小"就变成**系统性地少数** | 辐条投票 |
| 4 | **归一化 / 投票之前先问：这个量落在哪个尺度上？** 球头 6px 却把带切成 1.9px 一份 —— 切得比被测物还细 | 半径带切 3 份 |
| 5 | **「只能手工跑」的路径最容易烂。** 至少要有一个**构造级**离线测试把它钉住 | `--windowed` |
| 6 | **接口不一致的 bug 会只坏一半**（`QtRenderer` 好、`OpenCVRenderer` 坏）。凡是"两个实现同一个接口"，都要有一个测试**同时**按真实调用参数构造两者 | `actions` / `frames_drawn` |
| 7 | **"看着成功其实全错"最危险**：装配进度 4/4 + 大对勾 ✅，同时 `NG 缺失辐条`。**界面上的"通过"和判据的结论可以互相矛盾** —— 要信判据的数字，别信那个勾 | 真机假 NG |
| 8 | **归错类会浪费一轮**：把「两处算法不一致」当成「要不要开放位置」的附带项，结果它一直错着 | pose 对齐 |
