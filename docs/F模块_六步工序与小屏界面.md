# F 六步界面交付（2026-10-29）

本轮以Pi现有代码快照为基线，在独立副本中实现并逐项hash校验后同步至Pi。Windows旧代码及组员未提交改动未覆盖；只做F及任务书列出的integration/pipeline最小接线，不改A/B/C/D/E核心算法、模型、搜索、阈值、尺度或测量范围。

## 使用

Pi中运行：

```bash
cd /home/pi/assembly_vision
bash deploy/pi/run_ui6.sh
```

默认跟随桌面分辨率并全屏。I检测、R复位、F切换全屏、Q/Esc退出。浏览器仍通过已有noVNC SSH隧道访问，不需要接入实体屏幕。

六步为：底座→立柱→长度检测→轮盘→顶盖→顶盖深度检测。两项检测必须有效且合格才计入完成；提前取完四件不能跳过长度步骤。E仍是四件取件顺序，不变成六件。按现有候选人工框选，长度61～67mm、顶盖高度67.5～69.5mm；本轮没有重标定这些判据。

完成卡显示BINGO、本轮检测完成和总用时，默认5.5秒后收起；不自动复位。计时从D放行锁存开工到第6步合格，含等待、选区和复测，不含启动、开工前等待与完成提示。采用单调时钟；复位隔离代次；普通取消或同轮进度变化不会重新开始计时。

## 实现

- 新增ui/workflow.py：六步编排、同轮测量验证、计时、放回失效和一次完成事件。
- 新增ui/operator_view.py：最终画布字号、两行三列步骤卡、当前动作、受控范围、全屏大字与非阻塞完成卡；不拉伸视频。
- ui/base.py增加可选workflow契约，旧step/total仍保留四件语义。opencv_renderer.py仅在显式六步状态时启用新视图，并支持F键。
- integration.py为独立候选启用编排；pipeline.py传递真实取件/测量和复位状态，测顶盖保留长度结果，画面失效和故障抑制成功提示。同轮选区进度变化只取消本次测量，不清本轮计时。
- 新增config/abcde_integration_pi_ui6_candidate.yaml与deploy/pi/run_ui6.sh。两个旧入口与原候选均未覆盖；新入口明确使用OpenCV。

## 验证与证据边界

Pi全量34模块通过（原33+test_ui_six_step）；完成卡到期、重复回调、跨轮次、放回、无效/不合格、真实pipeline选区保留上一阶段等有回归。告警布局与进度变化修正后另跑针对性集成/阶段/渲染/六步回归。
